# ZAP — Implementation Plan

**Date:** 2026-04-20
**Spec:** `docs/superpowers/specs/2026-04-20-zap-design.md`
**Branch:** `feature/zap`
**Worktree:** `.worktrees/zap/`

## Execution order

Each step produces code that compiles and, where applicable, has tests. Commit
after each step.

### Step 1 — Registry generalization

Change the app registry so apps declare `accessMode` instead of `adminOnly`.

- Update `src/apps/registry.ts` `AppDef` type: replace `adminOnly: boolean`
  with `accessMode: "admin" | "allowlist" | "grant"`. Map existing entries:
  - `users` → `accessMode: "admin"`
  - `analytics` → `accessMode: "admin"`
- Update `src/lib/permissions.ts::canAccessApp` to branch on `accessMode`:
  - `admin`: user.is_admin && user.enabled
  - `allowlist`: user.enabled
  - `grant`: user.enabled && perms has matching slug
- `RequireApp` and `Dashboard` only read via `canAccessApp`; no changes.

Verify: existing Playwright specs still pass. (Any direct references to
`adminOnly` need updating.)

### Step 2 — Allow app sub-routes

Change `App.tsx` route pattern `/admin/apps/:slug` to `/admin/apps/:slug/*` so
ZAP can own its internal routes.

### Step 3 — Database migration + Storage bucket

Write `supabase/migrations/0003_zap.sql`:
- All `zap_*` tables from the spec.
- RLS helper `is_zap_trip_member(trip_id uuid)`.
- RLS policies as specified.
- `zap_add_creator_as_member` trigger.
- Storage bucket `zap-receipts` creation + RLS (via `storage.objects` policies
  keyed on the first path segment as trip_id).

Run `npm run supabase:reset` to confirm it applies cleanly against the local
Supabase stack.

Regenerate types: `npm run supabase:gen-types`.

### Step 4 — Pure balances module

Create `src/routes/admin/apps/zap/balances.ts`:
- `computeBalances(ledger)`
- `suggestSettlements(balances)`

Create `tests/admin/zap/balances.unit.spec.ts` using `@playwright/test`'s
`test()` API without browser fixtures. Cover:
- Empty ledger → empty balances.
- Single receipt, flat split among two members, payer is member.
- Single receipt, payer is not on receipt members list.
- Itemized receipt with tax remainder.
- Penny-rounding: $10 split 3 ways gives one member the extra cent
  deterministically.
- Settlement minimization: 3 users, 2 receipts → ≤ 2 suggested transfers.

### Step 5 — Edge Function `parse-receipt`

`supabase/functions/parse-receipt/index.ts`:
- CORS headers matching `request-otp`.
- Require `Authorization: Bearer <jwt>`; decode email; confirm the caller is a
  member of the trip encoded in the first path segment of `storagePath`.
- Service-role Supabase client downloads image bytes from `zap-receipts`.
- POST to `https://api.anthropic.com/v1/messages` with the image as a base64
  block and a structured-output system prompt. Model: `claude-haiku-4-5`.
- Parse JSON from the response's `content[0].text`. Validate shape. Return.

Write `supabase/functions/parse-receipt/index.test.ts` following the pattern
of `request-otp/index.test.ts` — uses Deno's built-in `Deno.test`. Mock
Anthropic via an injected fetch.

### Step 6 — ZAP client API

`src/routes/admin/apps/zap/api.ts`: thin wrappers around supabase-js:
- `listTrips()` — trips the current user is a member of, with member list and
  computed balance summary.
- `createTrip(name)`
- `getTrip(tripId)` — trip + members + receipts (with items + members) +
  settlements, plus signed URLs for receipt images.
- `addMember(tripId, email)` — validates via RLS; maps error codes to
  friendly messages.
- `removeMember(tripId, email)`
- `uploadReceiptImage(tripId, file)` → storagePath
- `parseReceipt(storagePath)` — invokes Edge Function, returns parsed fields
  or throws.
- `saveReceipt(payload)` / `updateReceipt(id, payload)` / `deleteReceipt(id)`.
- `markSettlementPaid({from, to, amount_cents, trip_id})`.
- `closeTrip(tripId)` / `reopenTrip(tripId)` / `deleteTrip(tripId)`.

### Step 7 — ZAP UI: trip list

`TripList.tsx` + CSS. Mobile-first, green theme. "New trip" button opens an
inline dialog; submitting calls `createTrip` and navigates into it.

### Step 8 — ZAP UI: trip detail

`TripDetail.tsx` composes:
- Header (name, close/reopen, delete).
- Members chip list + add member form.
- Balances summary computed with `computeBalances`.
- Settlement plan with "Mark paid" buttons → `markSettlementPaid` then refresh.
- Settlement history.
- Receipts list with thumbnails (signed URL) and tap-to-edit.
- FAB linking to `/admin/apps/zap/:tripId/receipt/new`.

### Step 9 — ZAP UI: new receipt

`NewReceipt.tsx`:
- Image picker (file input with `capture="environment"`).
- On pick: upload to Storage, then invoke `parseReceipt`, then render form
  prefilled with returned values.
- Form controls as per spec.
- Save → creates `zap_receipts` + children and navigates back to the trip.

### Step 10 — ZAP UI: edit receipt

`EditReceipt.tsx`: same form, prefilled from existing rows, no image
re-upload. Delete button.

### Step 11 — Register ZAP in the registry

Add `zap` entry to `APPS` in `src/apps/registry.ts` with
`accessMode: "allowlist"`, description "Split trip expenses." Sub-routes live
inside the ZAP component tree, not the registry.

### Step 12 — Playwright coverage

Under `tests/admin/zap/`:
- `access.spec.ts` — dashboard shows ZAP card for a non-admin enabled user;
  direct nav is accessible. Regression check on admin-only apps.
- `trips.spec.ts` — create trip, add member (happy path), attempt to add a
  non-allowlisted email (error surfaced), close+reopen, delete.
- `receipt.spec.ts` — with a Playwright route intercept of the Edge Function,
  upload a receipt, verify form is prefilled with the mocked response, save,
  confirm it appears on the trip.
- `settlement.spec.ts` — ledger of three users over two receipts; verify
  displayed balances and settlement plan; mark one paid; verify the plan
  shrinks and history grows.

Hook tests up via existing Playwright config. Use the existing auth-helpers
harness for signing in as arbitrary allowlisted users.

## Risk ledger

| Risk | Mitigation |
| --- | --- |
| LLM returns non-JSON / malformed | Validate response shape in Edge Function; fall back to manual form on parse failure. |
| Penny-rounding drift across balance + settlement phases | `computeBalances` stores integer cents only; deterministic tie-break. |
| Storage bucket RLS oversight | Manually verify via Playwright that a user can't read another trip's image. |
| Edge Function trip-membership check desync vs RLS | Always go through the Storage path's first segment; add a unit test. |
| Admin shell theme change lands concurrently | ZAP styles are self-contained; no dependency on shell colors beyond reading CSS vars already in `globals.css`. |
